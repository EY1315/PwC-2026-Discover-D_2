# 브리프체크

> 일을 시작하기 전, 질문부터 정리하세요.
> 업무 지시에서 빠진 목적·범위·마감·산출물·참고자료를 점검하고, 상사에게 보낼 확인 질문과 체크리스트를 만들어 주는 웹앱입니다.

삼일회계법인 2026 Discover · D-2조

## 파일 구성

빌드 과정이 없습니다. 파일을 고쳐서 커밋하면 Vercel이 그대로 다시 배포합니다.

| 파일 | 내용 | 주로 고치는 사람 |
| --- | --- | --- |
| `engine.js` | 판정 규칙(키워드), 질문 문구, 예시 문장, 체크리스트 할 일 | 콘텐츠·데이터 |
| `app.js` | 화면 구성과 버튼 동작, 저장 | 빌드·개발 |
| `style.css` | 색상, 글꼴, 레이아웃 | 빌드·개발 |
| `index.html` | 위 파일을 불러오는 뼈대 (거의 안 고침) | - |

## 자주 하는 수정 (`engine.js`)

### 1. 판정 키워드 추가

`ITEMS` 안에서 항목마다 `spec`(구체적 표현 → 확인됨)과 `vague`(애매한 표현 → 불명확)가 있습니다. 둘 다 없으면 누락입니다.

예: 마감에서 "말일까지"를 확인됨으로 보려면 `deadline`의 `spec` 괄호 안에 `|말일` 을 추가합니다.

```js
spec: /(\d{1,2}\s*월\s*\d{1,2}\s*일|...|\d+\s*시간\s*(?:안|내|이내)|말일)/gi,
```

- `|` 는 "또는"입니다. 단어 앞에 `|` 를 붙여 괄호 안 아무 곳에 넣으면 됩니다.
- `\s*` 는 "띄어쓰기가 있어도 되고 없어도 됨"입니다. (`다음\s*주` → "다음주", "다음 주" 둘 다 인식)
- 괄호를 지우거나 짝이 안 맞으면 앱 전체가 멈춥니다. 고친 뒤 꼭 미리보기에서 확인하세요.

### 2. 질문 문구 수정

`Q` 안에서 항목별로 `m`(누락일 때)과 `u`(불명확일 때)가 있고, 각각 `polite`(정중) · `friendly`(친근) · `clear`(명확) 세 가지 문구가 있습니다.
`{ev}` 자리에는 근거 문구(예: ‘다음 주’)가 자동으로 들어갑니다.

### 3. 업무 유형별 필수 항목

`LEVELS` 에서 `R` 필수 · `O` 권장 · `N` 해당 없음(점검 제외)을 정합니다.
예: 일정·행정 업무에서 산출물을 빼려면 `admin` 의 `output: 'N'`.

### 4. 예시 문장 · 체크리스트 할 일

- 입력 화면의 예시 버튼: `SAMPLES`
- 업무 유형별 준비 할 일: `TODOS`

## 작업 규칙

1. `main` 에 바로 커밋하지 말고, 브랜치를 만들어 Pull Request 로 올립니다.
   (GitHub 웹에서 파일 수정 → Commit changes → "Create a new branch" 선택)
2. PR 에 달리는 Vercel 미리보기 링크에서 예시 문장 6개를 눌러 보고 화면이 정상인지 확인합니다.
3. 확인되면 빌드·개발 담당이 `main` 에 합칩니다. `main` 에 합쳐진 버전이 심사용 링크에 반영됩니다.
4. 무엇을 왜 바꿨는지 PR 설명에 한 줄 남겨 주세요. 기획안 13쪽(Before → After) 근거로 씁니다.

## 로컬에서 열어보기

`index.html` 을 브라우저로 열면 바로 동작합니다. 점검 기록은 브라우저 저장소(localStorage)에만 저장되고, 외부로 전송되지 않습니다.
